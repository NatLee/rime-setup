## 已知未修的原版瑕疵（刻意保留，行為相容）

- **計算機警告字串拼錯**：`Waring`（應為 Warning）。
- **Unicode 區間註解與實作不符**：註解說「補後面 16 碼」，迴圈實際產生 17 個候選（含自身）。
- **超出 0xFFFFF 的內碼靜默無候選**：如 `'/x200000` 不出任何候選也不報錯。
- **`en_sort` 英文排序意圖偏差**：比較子第一句是死碼，實際退化為 byte 序，大寫全排在小寫前（`Zoo` < `apple`）。改動會影響既有排序習慣，故未動。
- **⇧2 在注音輸入時選不到字**：`@` 會先被 `recognizer` 的 email 樣式（`^[a-z][-_.0-9a-z]*@.*$`）接走，輸入變成 `su3@`。同理 `'/` 算式裡的 ⇧6（`^` 是算式合法字元）。日文 `6…`、英文 `3…`、`'/` 選單與 `'/u4e2d` 這類都正常。要救只能把 `p_select_keys` 移到 `recognizer` 之前，代價是不能再用 `@` 直接打 email —— 目前選擇保留 email。詳見 GOTCHAS。
- **prefix 未做 pattern 跳脫**：若把前綴改成含 `-` `.` `(` 等正則特殊字元會失效。現行前綴（`3`/`4`/`6`/`7`/`'/`）安全。
- **中文釋義品質上限**：來源是 WordNet 同義詞而非字典式定義，少數會被「假朋友」帶偏（如 `安い→安詳`）。已在詞典檔頭註明。

## 已評估但不做的項目

### 候選旁的獨立浮動小視窗（詞典 tooltip）
**結論：做不到，不要再嘗試。**
- 小狼毫只有單一候選面板，RIME 核心與 Weasel 都沒有第二視窗的 API 或設定。
- 唯一途徑是 fork Weasel 的 C++ 介面層自行編譯維護，且 macOS 鼠鬚管完全不通用。

### 「提示行跟著反白候選走」（退而求其次的方案）
**結論：技術上不可行，已實測。**
- `Segment.prompt` 可寫，寫入後**確實會顯示**在候選窗頂端（實測 `sa ku ra ▸ cherry tree...`），且能保留原生 tips、不影響中文段落。
- 但 `update_notifier` **只在輸入改變時觸發，方向鍵移動反白不觸發**（實測日誌確認）。
- 嘗試在 processor 內預判反白位置並提前寫入 `seg.prompt`：`seg:get_candidate_at()` 能正確取到下一個候選、`seg.prompt` 賦值後讀回也正確，**但前端讀到的仍是舊值**（mutation 未傳播）。
- 結果就是提示行只能反映「輸入」而非「選擇」，顯示錯誤資訊比不顯示更糟，故放棄。
- 替代方案（現行）：候選右側小字註解 ＋ `max_width` 自動折行。
